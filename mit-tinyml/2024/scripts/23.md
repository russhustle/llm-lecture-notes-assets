We have introduced how to construct quantum circuits, but on real devices, there is a large impact of noise when doing gradient computation. Noise can reduce the reliability of quantum computer gradients significantly. There is a noise-induced gap between two curves: one in blue is classical training (simulated on a classical device), and the other shows the actual parameter shift rule on a real IBM quantum device. The accuracy can be significantly reduced by noise on the actual device.

How can we deal with that? When the gradient magnitude is very small, the relative error will be very large. If we have a very large gradient value, noise is less likely to change the direction, but if the gradient is small, even a small noise can change the direction. The overall idea is to find very small values of the gradients and prune those unreliable gradients during training, only using reliable gradients to perform parameter updates.

We propose a method called probabilistic gradient pruning. Before pruning, in each training step, we update all the parameters. With gradient pruning, we only update parameters with reliable gradients. How do we know whether a gradient is reliable enough? We see how large the gradients are that we computed. Specifically, before pruning, we update all parameters; with pruning, we only update a subset with reliable gradients. To determine which subset is reliable, we use a window-based method: accumulate the gradients of multiple steps, sum the absolute values for each parameter, sort them, and only use those with large values for pruning. For very small gradients, we do not use them to update the parameters, ensuring we only use reliable information.

We compare quantum circuit training using probabilistic gradient pruning to others and are able to improve around 5% to 10% accuracy on four classification tasks. On the IBM device, we can achieve around 2x training time reduction because for unreliable gradients, we not only don't use them, but also don't have to compute them. The loss is always lowest on the classical device (no error), and the blue curve is QC training using the real device with parameter shift rule. Due to noise, there is a gap between the ideal and blue curves. With quantum on-chip training, we can close this gap and push the curve closer to the ideal case. On-chip training is also very scalable because we are not using any classical post-processing during the whole training pipeline—we compute gradients on the real quantum device and update the parameters. If using a classical simulator, the runtime and memory cost increase exponentially with the number of qubits, but with a quantum device, we don't have to pay that exponential cost.

We also compare probabilistic pruning to deterministic pruning. In probabilistic pruning, we use the magnitude of values to determine which parameter has a larger probability to be pruned, but the process is not deterministic—we are not always removing the parameter forever, but use sampling to sample different values for pruning. This gives some advantage compared to deterministic pruning, with around 1% to 9% increase in accuracy over several tasks.

That's the basic idea: train once, use many (similar to one-shot NAS in classical ML).

There are four steps: construct a super-circuit (large enough design space, e.g., three layers, each with four or nine gates, up to nine layers), train the super-circuit, do noise-aware evolutionary search of subcircuits and mapping, then after finding a reliable circuit, train it from scratch and perform pruning.

First, the super-circuit and subcircuits: we want to cover a large enough design space. For example, the super-circuit with U3 and CU3 gates has many candidates (subcircuits). During training, we use the super-circuit so we can just train it once. The issue for barren plateau is still there, but this method is orthogonal to circuit structure—you can start with a design space with better immunity to barren plateau, or during the search, evaluate gradients to find those without the barren plateau issue.

When using the super-circuit method, we want subcircuits to inherit trained values directly from the super-circuit, so we don't have to train them again. You may wonder how, because values typically cannot be inherited by all subcircuits. If we train those individually, even with the same location of gates, they may have different values. Here, we introduce a heuristic: sample and train. For each step, sample a subcircuit from the super-circuit, update parameters inside this structure, then in the next step, sample another structure and continue updating. After enough training steps, all subcircuits in the super-circuit have undergone the same number of training steps. Even if not the same accuracy as training from scratch, they can still indicate the relative performance order between subcircuits.

Quantitative results show a good positive correlation between the loss function for subcircuits with inherited parameters and the ground truth (trained from scratch). Since we only care about the order, we need this correlation to be large, so we can use the super-circuit to facilitate the search process. We can do evolutionary search inside the subcircuits, use reinforcement learning or any search engine, sample subcircuits from the super-circuit, evaluate performance on the real device, and iterate until we find the best subcircuit.

As learned in earlier lectures, pruning is also applicable to quantum machine learning. After training, some gates in subcircuits can be very close to zero. If a value is very close to zero, the actual unitary matrix is an identity mapping, so we don't have to implement the gate. For example, a rotation of zero degrees gives the same result as the input. We can perform iterative pruning of values close to zero.
