All right, welcome back. Let's continue to discuss Transformer design variants. Most of the initial designs have been widely used in the community, but people have designed several variants and alternatives. For example, the encoder-decoder model, encoder-only model, and the most popular decoder-only model. Also, people improved absolute positional encoding to relative positional encoding (only depending on relative position), and several KV cache optimizations, such as multi-query attention and group query attention (similar to normal convolution vs. depthwise convolution vs. group convolution—a tradeoff between capacity and computational complexity). Also, from the FFN to the gated linear unit (GLU), which is widely used these days compared to the original FFN layer.

Let's first talk about encoder-decoder, encoder-only, and decoder-only models. The original Transformer is actually an encoder-decoder architecture. For example, in translation tasks, we first encode the source sentence (e.g., English to German), pass it through the encoder model, and then the decoder model generates the output tokens. Here are more examples: translation, acceptability, semantic similarity (find the similarity between two sentences and give a score), summarization (given an input sentence, summarize to an output sentence). It offers a unified text-to-model for transfer learning on various NLP tasks. The prompt is fed to the encoder, and then the decoder generates the answers—first token, then second, then third, one after another.

The second category is the encoder-only model, like BERT (Bidirectional Encoder Representations from Transformers). It is an encoder-only language model with two pre-training objectives: masked language modeling (widely used) and next sentence prediction (not widely used these days). Masked language modeling means we can mask away, say, 15% of input tokens at random, then train the model to predict those masked tokens. The masked token can see both the tokens before and after it. For example, "The movie is very boring," we put a mask and pass it through the encoder, then try to predict the mask. Next sentence prediction gives two sentences and predicts whether sentence B is the next sentence of sentence A. The pre-trained model can be fine-tuned for downstream tasks. The attention mask for encoder-only models is full, because each token can see both previous and future tokens.

Decoder-only models: the attention mask is only the lower triangle, since a token can only see previous tokens, not future tokens. GPT stands for Generative Pre-trained Transformer, which is a decoder-only language model. The pre-training objective is next word prediction: given a sentence, predict the next word. That word can only attend to the tokens before it; therefore, the attention mask is causal. The pre-trained model can also be fine-tuned for downstream tasks, but larger models don't even need fine-tuning—they can have zero-shot and few-shot capabilities, which we will discuss later. You just tell the task or give a few examples without having to fine-tune on a particular task, and they can realize new tasks.

Now, let's switch to absolute positional encoding versus relative positional encoding. Absolute positional encoding fuses the positional information into the input embedding and also the Q, K, V, so the information propagates through the entire Transformer. Relative encoding keeps an eye on the relative distance information by impacting only the attention scores (not the input embedding), by adding a bias or modifying the parameters of keys (not the value). The attention map only depends on Q and K (QK transpose). An advantage is that you can deal with long context, e.g., reading a whole book or movie. During training, we may not have seen such long contexts, but we want to train on short and infer on long. That's the advantage of relative positional encoding—it is easy to extrapolate for long context at inference time.

We introduce two kinds of relative positional encoding: attention with linear biases (relative position encoding), and RoPE (rotary positional encoding). Let's start with the first. The idea is to change the positional encoding to be only related to the relative distance. For example, Q1 and K1: relative distance is zero; Q2 and K1: relative distance is one; Q4 and K2: relative distance is 2-4 = -2, etc. We add this offset to the original attention matrix, defined as the relative distance, instead of adding to the input token embedding. The input token doesn't change, but only the attention map changes. The strength is multiplied with this positional encoding and added to the original attention map, so you can capture the information between the relative distance of two tokens.

The second one, RoPE (rotary positional encoding), is more challenging but widely used (e.g., in Llama). We want to rotate the embedding in a 2D space. To do that, we first split the embedding dimension D into pairs, so we have many pairs (D/2). Each pair becomes a 2D value (x1, x2), which we can represent in 2D space. We rotate by m\*theta, where m is the position of the token, and theta is related to the hidden dimension. We rotate the representation by grouping every two values into a 2D space and then rotating it. When we multiply Q and K using the rotated value, the phase value is the difference between the phase of Q and K, so it only depends on the relative position (m-n). That's why we call it relative position encoding.

What is good about RoPE? We can extend the context window to process very long documents, books, or movies. For example, Llama 1 had a 2K context length, Llama 2 became 4K, GPT-4 used to be 8K, but with larger context length. We can extend the context length by interpolation. For example, if we double the context length, we rotate by m\*theta/2. During pre-training, the range is from 0 to 2K; now we interpolate from 0 to 4K, putting more dots in between, so we fit a longer context.

Now, let's talk about the KV cache. Multi-head attention and group query attention: the KV cache can be pretty large in long context cases. For example, with three tokens ("I love chromium"), we project into Q0, K0, V0, Q1, K1, V1, Q2, K2, V2, and calculate the attention score for a new word by multiplying Q2 with K0, Q2 with K1, Q2 with K2, etc. We use this as a weighted sum for the values (V0, V1, V2). We need to store these keys and values for all previous tokens to perform the attention computation. Without a KV cache, we need to recompute each time. With a KV cache, we only calculate everything related to the new token and store everything before that in the cache. As a result, the KV cache will get longer as the sequence gets longer.

How do we calculate the size of the KV cache? For a 7B model, the KV cache is: batch size × number of layers × number of heads × hidden dimension × sequence length × 2 (for key and value) × 2 bytes (for fp16). For Llama 2 7B, that's half a megabyte per batch size per token. For Llama 2 70B, it's 2.5 megabytes per batch size per token. That can get pretty big. For example, if the batch size is 1 and the sequence length is 4K (about a paper), it will take 10 gigabytes just to store the KV cache. For 16 users, that's 160 gigabytes—each A100 GPU has 80GB of memory, so only storing the KV cache for 16 users requires two A100 GPUs, which is expensive. The KV cache can even exceed the model size as the number of users increases.

How do we deal with that and save the KV cache? By sharing some of the keys and values. That's the idea for multi-query attention (MQA). In multi-head attention, you have N heads for query, key, and value. In MQA, you still have N heads for query, but only one copy for key and value. This reduces the KV cache size, but unfortunately, it loses a lot of model capacity. The tradeoff in the middle is group query attention (GQA): you have many queries as before, but a group of them (e.g., every eight queries) share the same key and value. This is similar to group convolution—a tradeoff between model capacity and computation.

How does GQA and MQA help? MQA has the lowest KV cache size (one copy of key and value), GQA is in the middle (e.g., eight queries share one key/value), and multi-head attention has the largest (one per head). The reduction is significant: previously, 320GB for 70B model (can't fit on a single node), now below 80GB (can fit on a single H100 node). Accuracy-wise, GQA can match the accuracy of MHA in very large models.

The last change is from FFN to gated linear units (GLU). The difference is that FFN consists of two matrix multiplications with a nonlinearity in the middle, while GLU has three matrix multiplications and an elementwise gating function between two tensors, then passes through another matrix multiplication. The activation function is different (switch activation). These two matrix multiplications can be fused into a single one. Complexity-wise, using GLU gives good results. Comparing different activation functions, the switch and GLU look similar, but there are subtle differences.

For example, translation: give an example, calculate gradient, update the model, repeat, and finally get a new model.
