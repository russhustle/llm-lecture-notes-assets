The last technique is batching. Why do we need batching? Running multiple inputs simultaneously in parallel can maximize the throughput by fully utilizing the GPU resources and avoiding idle time. There are several batching methods. Of course, the simplest way is no batching: when a request arrives, we just immediately process that; we may underutilize the GPU resource. Static batching, which is waiting for a full batch of requests before we can process them, is pretty good for offline tasks like scheduled tasks: you have like 10,000 images to label, take overnight, and then you can use static batching, but it will increase the latency for real-time tasks; you may have to wait for the batch to be full before you process them.

There's also dynamic batching: the batches are processed either when the batch is full or a set predefined time has arrived. The last part is continuous batching, also called inflight batching, which has a finer granularity, token by token. Let's see an example of dynamic batching: static batching, basically, you have to wait for four token requests to arrive, which may take a long time. Here, it takes a long time. This is good for generation tasks with uniform inference latency, like image generation: you have a predefined, fixed amount of inference latency.
